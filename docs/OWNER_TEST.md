# Your final check

For public repository onboarding, fork contributions, commit history and follow-up
requests, see [the contribution workflow](CONTRIBUTING_FLOW.md).

Forge is inside GitHub. There is no separate website to visit.
The current model selection is OpenRouter's free Inkling route. Add your OpenRouter
key in **Models & API keys** to activate it. The previous Groq configuration remains
in a private local backup. Docker is not used. Repository selections are explicit;
publishing still requires approval of the exact proposal.

See [model connections](MODEL_CONNECTIONS.md) for API-key, endpoint and CLI/environment
options, multiple profiles, and spending permission modes.

## Load the companion

1. Open `chrome://extensions` or `edge://extensions`, turn on Developer mode,
   choose **Load unpacked**, and select this project's `extension` folder.
   The release ZIP can also be extracted and loaded that way.
2. Click the Forge toolbar icon. In Connection, use `http://127.0.0.1:8787` and paste
   the token from `.forge/owner-token`. Keep that token private.
3. Open either real acceptance issue:
   - [Python page-size fix](https://github.com/KaartikeyKusshwaha/Forge-Acceptance/issues/1)
   - [TypeScript discount fix](https://github.com/KaartikeyKusshwaha/Forge-Acceptance/issues/2)

## Review the real proposal

Click **Forge**. It should reopen the ready proposal for that issue.
In **Progress**, inspect the plan and cited source files. In **Changes**, inspect
the proposed product code and regression tests. In **Checks**, verify that the
baseline passes, the regression fails on the original code, and the candidate
passes. Real runner links are included in the stored evidence.

Choose **Suggest changes** to type a correction, feature addition, or missing
requirement. The dialog retains your draft if submission fails. Submitting retires
the old proposal and starts a fresh model run with checks and a new approval step.
This works for ready proposals even after their approval window expires.

**Recent runs** includes published PR numbers and timestamps. Open a run's
**Timeline** tab for its complete Forge activity. After publication, choose
**Refresh GitHub timeline** to retrieve the PR's current open/closed/merged state
and GitHub milestones. Refresh is manual; up to 100 GitHub events are shown, plus
current closure and merge milestones. This tracks PRs created by Forge, not every
PR in your GitHub account.

After pairing, Connection shows a connected workspace instead of token entry.
Use **Change connection** only to replace the endpoint or token.

The Python proposal passed 9 candidate tests and the TypeScript proposal passed
4. Both were generated by the actual Groq model. These two smoke tasks are not a
general reliability benchmark. A previous false planner stop remains in history
and is documented rather than hidden.

If satisfied, click **Approve and create draft PR**, acknowledge the CI notice,
then confirm. This is the first target commit/push/PR action. Forge must never
merge it. Reject and Download patch are also available. Request revision retires
the old candidate and starts a fresh run.

Approvals are time-limited. If a proposal expires, choose **Refresh proposal and checks**; Forge rechecks the
current base instead of silently reusing old approval.

## If the local service has stopped

From this project folder, run `./scripts/start-forge.ps1`. Your Groq key stays in
the ignored `.env`; it is not in the extension or public repository.
`uv run forge doctor` shows readiness without displaying credentials.

Do not add private or production repositories for this check. The dummy repository
has no deployment workflows or secrets. Your other projects are not allowlisted.

The GitHub App registration flow remains available for App-based installations.
The prepared personal setup uses the existing local GitHub CLI account and an
explicit allowlist, so you do not need to create an App just to do this check.
